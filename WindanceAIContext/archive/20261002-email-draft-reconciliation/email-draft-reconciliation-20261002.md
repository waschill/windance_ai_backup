# Durable draft evidence and positive reconciliation, staged

October 2 UTC / October 1 Mountain 2026. Local component work only; previous private full Harness candidate has not yet been rebuilt with this module revision.

Recoverable draft preparation now computes its operation marker and MIME fingerprint before the callback. A separate private evidence table is inserted in the same transaction as the unconfirmed action intent, retaining source message ID and expected thread for later recovery. No recipients, subject or body are duplicated in that table; request/payload hashes bind the content. The callback receives the exact prepared raw MIME. Existing plain journal calls retain their behavior and old unmarked intents cannot be guessed into this evidence path.

Reconciliation reads an existing draft intent and versioned bound evidence, performs the staged two-call maximum read-only lookup, and updates only the local journal when one exact draft matches. Before that update, it re-reads the full local evidence/intent tuple inside a write transaction and rejects any intervening change. The minimal draft receipt and reconciliation timestamp commit together. It creates, sends, deletes or modifies nothing remotely. A successful observation is point-in-time evidence, not a guarantee the owner will never edit the draft afterward; later send approvals still need fresh context.

Four connected synthetic cases passed: accepted draft/lost response then exact read-back; no matching draft; edited content; local evidence drift during lookup. Each creates one synthetic draft. Only the exact match transitions the local journal to confirmed, and replay returns the recorded ID without invoking creation. All other outcomes retain the hold. Three real child-exit and competing-process tests were rerun after the schema/module changes and passed.

The first local Windows run reached fixture cleanup with a still-open SQLite handle. Fixture connections now explicitly close, and the corrected run passed. This was a test-lifecycle defect, not a production failure; no live database was involved. The process test was similarly made explicit about closing parent fixture connections for Windows portability.
