# Receiver pause lease tests — 2026-10-02

Prepared receiver_pause_guard.py as a short-lived POSIX pause lease, not an installer. It accepts a bounded PID/identity/duration record, verifies process start/command signature and that the process is not already stopped, sends SIGSTOP, verifies stopped state, then resumes on explicit input, controller-pipe EOF, expiry, SIGTERM or SIGINT through cleanup. Duration is at most15seconds; ps inspections have individual1second timeouts. It has no launchctl, queue mutation or message-sending capability. A future installer must independently verify the target is the expected live service and remain within the lease, not blindly use a recorded PID.

SAL real-signal tests passed five cases on test-owned child processes only: explicit resume, controller stdin loss, lease expiry, wrong identity rejected without pausing, and terminating the guard after pause resumes its worker. A synthetic heartbeat file stopped changing during pause and resumed afterward. Every worker/guard was cleaned up. Zero production processes signaled or real messages sent.

Limits: current tests simulate controller disconnection by closing its pipe, not complete SSH transport death. Abrupt SIGKILL of the guard itself, host failure, or failure of process inspection during cleanup can prevent automatic resume; those are not proven handled. Identity uses ps start time plus command hash, not a kernel-unique process handle. It is a risk-reduction mechanism, not a perfect liveness guarantee. No deployment uses it yet. A full old-receiver/lease/busy-state/service-removal rehearsal is still required before live cutover, including queue arrivals while paused and abort/resume on any in-flight marker. Do not call this a completed receiver transition.

Signal-interruption handling was added before publication after review of the initial helper: default SIGTERM could otherwise leave the worker stopped. The revised five-case suite passed. Preserve this finding as a design correction, not a production incident.

Next: rehearse the complete transition against the pinned original receiver with synthetic transport, prove no in-flight receiver termination and retained new arrivals, then coordinate current ownership/fresh backup before installing the same-label service candidate.
