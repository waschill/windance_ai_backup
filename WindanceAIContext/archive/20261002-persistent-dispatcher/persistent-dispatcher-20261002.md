# Persistent receipt dispatcher staged — October 2, 2026

Added receipt_outbox_dispatcher.py with explicit root/source/Message-store/wheel paths. It owns dispatcher.lock nonblocking, chooses one queue item per iteration, invokes only its fixed sibling request worker through the existing guardian, then rotates its in-memory cursor past held items. Worker still takes the original owner.lock, so existing live daemon excludes entry. CLI --once supports isolated checks; no service registration or implicit paths. Per-request budget validates0<seconds<=600(default600);0.5second polling delay. Whole process exit is never recorded as delivery.

Worker now returns exit75 for owner contention and20 for a contract hold; processed paths return0, with durable receipt/result still authoritative. These codes are worker-control signals, separate from wire receipt codes. Legacy handler semantics remain pinned; no legacy receipt upgraded.

SAL actual dispatcher/supervisor/worker no-send cases pass: empty queue idle, duplicate dispatcher blocked, old owner lock prevents handling, retained legacy result unchanged with queued copy cleaned, and marked request with missing journal quarantined. Persistent-loop fixture keeps one invalid held filename while processing later retained-result items, proving cursor rotation prevents that held item starving them. Process was confirmed running during observation then explicitly terminated/reaped. Full marked admission/receipt/stall regression also passes after worker exit-code change, though that regression invokes the supervised worker rather than persistent dispatcher.

Limitations: actual new synthetic sends through persistent dispatcher are not yet composed in one fixture; existing tests separately cover sender worker and dispatcher. Queue names are enumerated/sorted per iteration without a resource cap; pathological backlog limits remain open. Default600-second request budget must be checked against actual legacy chunk sizes/consumer policy before rollout. No launchd definition/cutover exists yet, no automatic consumer switch. Parent-loss and legacy send interruption at this persistent layer need exact integration evidence rather than inference from sibling tests. Current complete recovery archives are historical relative to dispatcher changes.

No production service, schedule, sender, task dispatch, SAM/Odoo/SyncThing/Level8/Warden/phone/routing change. Synthetic queues only, no real sends or application model calls/purchases. Codex cost unknown. Phase1 open; historical-send, caller coverage and coordinated cutover remain gates.
