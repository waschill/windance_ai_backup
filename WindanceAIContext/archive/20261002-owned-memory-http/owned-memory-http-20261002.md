# Owned-memory HTTP integration candidate

Added a staged FastAPI router for /memory/owned/facts and /memory/owned/query. It requires explicit owner/channel/scope plus a scoped bearer credential independent of the existing trusted-host middleware. Mutations require stable event IDs and expected revisions, use the atomic source/request ledger, and return metadata receipts rather than raw fact values. Queries use canonical owner/scope/grant-filtered storage. Conflict, denied access and unavailable storage have distinct status codes without exposing database errors. A supplied content validator must accept content before storage; delete requests cannot carry replacement content.

Mounted this router on the actual currently installed Harness app in a separate HERALD process with temporary DATA/LOG/CONFIG/Google-config directories and a disposable fact database. The application interpreter and FastAPI/httpx in-process ASGI transport were used; no socket listener, live router mount or production configuration change occurred. Network/subprocess/model/dispatch paths were intercepted during requests. Test credentials and content were synthetic.
