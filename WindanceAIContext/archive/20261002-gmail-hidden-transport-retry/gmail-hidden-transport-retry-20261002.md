# Installed Gmail transport can replay writes below execute(num_retries=0)

Live read-only inspection of HERALD's installed Python libraries found googleapiclient default HTTP timeout60seconds, Google requests refresh timeout120seconds, and google_auth_httplib2 AuthorizedHttp default max_refresh_attempts2. More significantly, httplib2.Http._conn_request has a response-error reconnect/retry branch even when the application sets HttpRequest.execute(num_retries=0).

test_gmail_hidden_retry.py ran against installed httplib2 0.32.0 and the actual googleapiclient HttpRequest.execute. A fake connection recorded POST requests and supplied either BadStatusLine or ResponseNotReady on the first response read, then a successful synthetic response. Each of two cases called execute once with num_retries=0, issued two transport POST attempts and returned success. No socket, Google credential, mailbox message or external API was involved. This proves the installed retry behavior under the simulated connection failure; it does not prove any historical live duplicate.

Observed _conn_request source SHA-256: 59fe2b0a6d00ee56757780c7977584a742052641fc6f1ee0ddda988ac7e4a499. Existing candidate b30bd912's durable operation intents surround the application invocation and therefore do not by themselves prevent a second write inside this lower layer. Earlier journal tests remain evidence for the boundaries they simulated, but are insufficient for an end-to-end no-duplicate claim. This is an additional deployment blocker, not a reason to reset or replay unknown operations.

Next correction must provide and test a Gmail-specific transport with explicit bounded requests and no automatic replay of potentially completed writes, including lower-layer connection and authorization retries. Test actual client composition under dropped response, malformed response, timeout, redirect and401conditions. Preserve unknown-outcome intents on failure. Do not change global library retry constants or shared Calendar behavior as an incidental fix. Socket timeouts alone are not a hard end-to-end job deadline; worker cancellation/deadline enforcement remains separate.
