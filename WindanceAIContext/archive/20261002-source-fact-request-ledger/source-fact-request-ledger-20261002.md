Live source trace found direct remember_text receives channel:user as its source and message_sync inserts the conversation afterward. The action gateway instead passes an action-plan reference. Neither supplies the staged fact store with a transactionally bound, authenticated immutable source event yet. Added staged owned_fact_requests and source_fact_gateway.apply_fact_request. After scoped credential binding, a stable issuer/event ID and canonical payload hash identify the request. Fact revision, history and result receipt commit in one transaction. The fact's source reference points to this durable request ledger. Equal retries return the receipt without changing the fact; conflicting content under the same ID rejects. Replays after correction/deletion report superseded and do not resurrect values. Receipts retain metadata/hash rather than raw fact text. Source/fact failure rolls back the whole operation. Existing direct storage API still refuses accidental caller transactions; joining a transaction is explicit and internal to the new gateway.

Limits: issuer authentication is currently synthetic policy wiring; real adapters/credentials, protected transport and manager/worker identity propagation remain unfinished. The ledger proves what a bound adapter requested, not that a remembered proposition is true or that external source material supports it. Secret rejection and source-content validation must precede the gateway. No source raw-text archive is added here; evidence hashes and source identity are retained. Existing conversation/backups/mirrors are separate and not erased by fact deletion. Actual remember/correct/forget/share routing, reflection scope, source revocation, legacy classification, semantic/fallback integration and mirrored copies still need implementation. Do not claim end-to-end memory acceptance.
