# Scoped memory ingress candidate

Candidate only; no live credentials generated/read, no endpoint or caller changed.

memory_ingress_policy.py binds a bearer credential to an explicit server-side tuple of owner/channel/scope/operation permissions. Missing owners do not default to William; a payload cannot exceed the credential's grants. Background fixtures can write a business fact without being allowed to read or write personal facts. Multi-owner adapters require explicit combinations rather than separate lists that accidentally grant every combination. Resolver results are immutable, credential representations omit credential values, and failures use generic messages.

save_fact/read_fact integrate this binding with the staged owned_fact_store. Nine ingress tests plus eight storage tests passed on HAL (17 total), using synthetic credentials and in-memory SQLite. Cases include equal-key privacy, forged owner rejection before mutation, malformed/unknown/missing credentials, wrong channel/scope, service restrictions, correction/deletion, credential-policy revocation and multi-owner combinations. The initial missing-owner test failed in test fixture string concatenation before invoking the policy; the fixture was corrected and all tests rerun successfully. No production HTTP handler integration or real sender verification is claimed.

Remaining deployment gates: inventory each live caller and required capability; securely provision separate credentials without exporting secrets; protect bearer transport; bind real sender mapping and reject ambiguous/group provenance; propagate immutable identity through manager/workers; integrate source-reference verification, secret rejection, read/share endpoints, grant audit, scoped retrieval and derived-copy invalidation. A multi-owner adapter is trusted to authenticate its upstream sender, and compromise of that adapter is not addressed by this component. Caller payload source_ref is only structurally validated here. The module does not provide TLS, replay/idempotency enforcement, rate limiting or general request authentication. Policy configuration must be trusted and immutable; production loader not implemented. Legacy SAM/report callers remain unchanged pending compatibility tests.

Do not install the reader-only or storage-only candidates as if the full privacy boundary were complete. No migration, production schema write, model call, Odoo access, send, restart or SAM interruption occurred. No new dependency or charge. Recovery is not deploying the staged files; production rollback requirements remain to be prepared for the complete packet. Phase 1 remains open.
