# Bounded caller status reconciliation staged — October 2, 2026

Added bounded_outbox_status.query as a read-only caller building block. It starts a fixed sibling worker, passes root/key/body over stdin rather than process arguments, and applies a parent-local total wait budget up to55seconds from before spawn. Pending queue state is polled; verified journal-backed delivery, legacy submission, uncertainty, conflict, unknown or unavailable returns immediately. Timeout kills/reaps the reader and returns unknown/status_wait_expired with query_same_request_only. It never enqueues, deletes, clears holds or treats process success as delivery.

SAL tests: ten retained-state fixtures pass and preserve every file byte. Queued work under0.4-second wait returns explicit expiry rather than failure/retry permission. Forged receipt without matching journal is unavailable; legacy ok remains unverified submission. A separate synthetic publisher made journal-backed result available after0.25seconds; query observed verified delivery in0.379seconds. Repeated query preserved all bytes including the queued item. Zero sends and no private production data.

The55-second maximum reserves25seconds relative to existing80-second outer callers, but this is not yet a complete end-to-end budget proof: queue admission, SSH/authentication, status transport and process cleanup also consume time. Existing enqueue uses a blocking claim lock and non-fsynced writes; its admission path is unchanged and must be addressed/contained before a coordinated switch. No live caller uses this new query yet. The inner worker accepts trusted local paths and data, not an authenticated network API. Reads/OS scheduling/reap are not hard realtime; parent crash may leave a read-only worker until separately terminated. No messages can be sent by this module.

A currently inflight request returns uncertainty, not a delivery claim; callers may later query the same stable identity. Missing/claim-only history never authorizes automatic enqueue. SMS remains unsupported by the independent iMessage receipt proof. Existing caller exit-code assumptions and wrappers require explicit integration before rollout. No production service, schedule, SAM, Odoo, SyncThing, Level8, Warden, phone or route changes. Staged files local/SALtmp only; immutable release r1 unchanged. Phase1 remains open. Application model calls0; Codex cost unknown.
