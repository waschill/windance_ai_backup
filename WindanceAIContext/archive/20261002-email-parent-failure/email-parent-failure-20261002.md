# Email worker parent-failure tests

October2. The standalone trusted-worker prototype now has an independent POSIX ITIMER_REAL timer with default SIGALRM termination and a daemon parent-identity watcher. The parent PID and bounded lifetime come from the supervisor, not the email payload. The timer is armed before worker import. The watcher checks the expected parent every50milliseconds and exits125 if reparented. These supplement the supervisor's deadline/output checks and exact child kill/wait. No production endpoint or private Harness candidate imports this prototype yet.

Actual HERALD test killed the supervisor after an actual durable intent and a synthetic effect were persisted. Child disappearance was observed after0.041seconds, the delayed fixture effect was absent and the SQLite intent stayed unconfirmed. A separate test suspended the supervisor with SIGSTOP; the child's independent0.4second timer terminated execution, observed after0.418seconds, and the delayed effect remained absent. The test resumed and reaped the supervisor. This proves the fixture's terminal state without relying on the supervising Python loop; a zombie state, if observed, is terminal execution but is not a reaped process.

Existing timeout/journal retry, excess-output, prohibited Python child dispatch, unrelated-file-size and normal-receipt tests pass again. The0.5second timeout case returned in0.504seconds with child absent and no second fixture effect on retry.

Limits: tests use trusted Python workers and local synthetic data, not full Harness report/HTTP integration or actual mailbox identity. This is not a native-code sandbox; trusted/native code could alter signals or bypass Python audit hooks. Parent death detection is not atomic with a remote write: an in-flight action may have succeeded before shutdown and must remain uncertain until reconciled. Kernel/host failure, signal masking, application cleanup and real provider state are not certified. Independent timer bounds start at child bootstrap; process creation and OS scheduling can add latency. No claim of exact universal wall-clock timing is made.

Next gate: fixed allowlisted worker entry points, source-manifest checks, actual caller ownership propagation and complete email workflow tests. Keep transport/cache/journal candidate and production separate until that evidence exists. Never clear uncertainty or replay because a worker died. No live rollback required; this prototype and test files are inert unless invoked. Publication contains only sanitized code and fixture paths; no actual credentials or mail content.

No service install/restart, external send, Odoo/SAM operation, schedule, Warden, SyncThing, Level8 or phone change occurred. Existing software only, zero application model calls and no new paid commitments. Codex usage and dollar attribution remain separate. Phase1 is open.
