# SAM atomic source-checked finalization, staged

sam_source_guard.py computes a deterministic fingerprint from schedule items, existing completion details, carry suppressions and carry records. finalize begins an immediate SQLite transaction, compares the expected source fingerprint, and only then marks the day committed with its exact receipt in the same transaction. An already-completed day accepts only the same stored receipt. The memory client's receipt validation remains required upstream; this helper alone does not establish remote acceptance.

Seven tests against the actual r4 SQLite schema pass: normal/repeat completion, changed item, deleted item, changed carry state, changed suppression, a different receipt for an already-completed day, and a separate thread attempting a write between fingerprint comparison and completion. That competing write receives SQLite locked; it cannot slip through the finalization transaction. The fixtures close/remove their databases and pass integrity_check. No actual SAM, Odoo, memory API, model, message, schedule or service call occurs.

This is a required component, not full integration. The next candidate must acquire a coherent initial source/schedule snapshot and capture the expected post-rollover token in the same transaction as the rollover result. It must avoid treating its own derived display changes as business edits. Carry selection currently uses all carry rows, so the token conservatively includes all of them and can hold on unrelated carry edits; a narrower dependency must be justified before relaxing this. Subsequent user edits must invalidate completion and use a supported memory-correction path. The remote first-clear Boolean race remains unresolved. No deployment readiness or pilot completion is claimed.

The initial connection/version assumptions and production SQLite journal mode still require full-service verification; this test establishes the locking behavior of the isolated fixture. Existing training details are included only as source rows, with no collection enabled. Source values are hashed locally and not included in test output or publication.

Recovery: no production rollback is necessary. The helper and test are local stage files. Reproduction requires the pinned private r4 source under sam-memory-r4-private; the shared packet excludes it. R4 remains failed/uninstalled. Costs: no application model or paid service calls; Codex consumption and project dollar attribution are separate and unmeasured here.
