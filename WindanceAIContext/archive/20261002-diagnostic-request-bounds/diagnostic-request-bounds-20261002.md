# Diagnostic request stream and validation privacy bounds

Staged only. The diagnostic API now applies a4096-byte body ceiling before JSON parsing and a10-second total body-read deadline. It checks actual fragmented bytes rather than trusting Content-Length. Duplicate, malformed and mismatched lengths fail closed; disconnects do not enter a handler. Errors return fixed metadata. RequestValidationError responses now omit input values, preventing framework validation responses from echoing arbitrary private fields. No request-body logging was added.

On HERALD's existing application Python, raw ASGI tests passed oversized single/fragmented bodies, oversized declared length, mismatch, duplicate/negative lengths, slow input and mid-body disconnect. Rejected input created zero job rows. A valid fragmented submission created exactly one fixture job. A separate private-sentinel invalid payload returned422 with neither the submitted field nor value. The existing twelve-case API suite also passed authentication, owner separation, idempotency, changed-evidence conflict, concurrent claim, cancellation uncertainty and cold recovery. No worker dispatch or real network listener was used.

Limits: this bounds each application request body and its read duration, not connection concurrency, HTTP-server header buffers, reverse-proxy buffering, request arrival rate, total ledger growth or all response streams. A server may allocate an incoming ASGI chunk before application checks it. Application body-timeout middleware does not replace deployment server limits. Authentication still uses the existing explicit server mapping; real credential provisioning/UI and persistent consumer remain unfinished. Generic diagnostic reasoning and original pilot acceptance remain open.
