process_one takes the same exclusive nonblocking owner.lock as the existing daemon before queue handling. Missing directories are rejected; missing history is quarantined rather than provisioned. Existing daemon ownership therefore prevents this worker from entering its queue. This is a proposed replacement execution boundary, not a second simultaneously active dispatcher. Caller must invoke it through the whole-request supervisor; direct CLI execution alone has no whole-request timeout.
