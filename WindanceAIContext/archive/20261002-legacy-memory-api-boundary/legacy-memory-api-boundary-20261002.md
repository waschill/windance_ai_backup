## Required containment before privacy acceptance

The new authenticated conversational memory path cannot be treated as an enforced privacy boundary while a user-facing worker can call unrestricted legacy memory APIs or read the underlying shared files. Restrict legacy routes with server-owned service capabilities, reconcile each existing scheduled/SAM writer and reader against a supported replacement, and withhold entries lacking verified owner/scope rather than guessing. Direct full-access worker filesystem/tool reach is a separate boundary; a bearer-scoped API alone does not constrain it. General source-aware retrieval and legacy/mirror handling must be integrated coherently before accepting multi-owner privacy.

Do not blanket-disable the legacy routes during protected operations or silently break existing deterministic producers. Use the caller inventory, inspect actual registrations and work ownership, prepare explicit service scopes and verify each surviving caller in isolation. Do not turn trusted-host membership or a caller-supplied owner into person authentication. No new permission request is needed for this scoped implementation work; no live change is made in this packet.
